# Сравнение Git и SVN

## 1. Почему в Git ветвление дешевое, а в SVN дорогое?

В Git ветка представляет собой легковесный указатель на коммит. Ее создание не требует копирования файлов и выполняется локально почти мгновенно. В классическом SVN ветки создаются как копии каталогов внутри централизованного репозитория. Хотя сервер использует оптимизацию copy-on-write, работа с ветками сильнее зависит от структуры репозитория, сетевого соединения и централизованных операций.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, обычный коммит SVN без подключения к серверу выполнить нельзя. Централизованный репозиторий хранит общую историю на сервере, поэтому для фиксации новой ревизии клиент должен передать изменения серверу. Без сети можно редактировать локальную рабочую копию, но создать полноценный коммит нельзя.

## 3. В каких сценариях SVN может быть предпочтительнее Git?

SVN может использоваться в существующих legacy-проектах, где уже настроена соответствующая инфраструктура и миграция слишком затратна. Он также может быть удобен при централизованном контроле доступа к отдельным каталогам и при хранении больших наборов бинарных файлов, когда разработчикам не нужна полная локальная история репозитория.
